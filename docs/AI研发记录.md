# 振动监测 AI 研发记录（零基础可读版）

> 项目：STM32F407 工业振动监测 · 故障诊断
> 结论先行：**5 个特征 → 16 → 8 → 3 的微型神经网络，259 个参数，int8 量化后零精度损失，96.2% 测试准确率，跑在 168MHz 单片机上，推理一次不到 1ms**

---

## 第 1 章 我们要解决什么问题

电机有三种状态（工况）：

| 状态 | 实物操作 | 振动特征 |
|------|---------|---------|
| 正常 | 原样运行 | 平稳、振幅小 |
| 螺丝松动 | 拧松固定螺丝 | 低频晃动 |
| 转子不平衡 | 加偏心配重 | 剧烈周期振动 |

**AI 的任务**：每秒读一段振动数据，判断当前是哪种工况。

**为什么不用"阈值判断"？** 拿 RMS（振动强度）举例：正常 ~550mG、松动 ~150mG、不平衡 ~2200mG。如果只看 RMS，"不平衡"（大）和"正常"（中）能分开，但**松动反而比正常还小**——一条规则写不穿三种工况。神经网络的价值就是自动找到"哪种特征组合 + 什么权重"能把三类分开。

---

## 第 2 章 什么是"特征"——给 AI 看的体检指标

ADXL345 加速度计以 1kHz 采样，128 个点做一次 FFT（快速傅里叶变换）。

**FFT 做了什么**：把"时间序列"（128 个数字，看不出规律）变成"频谱"（16 个频点，每个频点 = 这个频率的振动有多强）。分辨率 7.8Hz/bin：

```
bin0=0Hz(直流)  bin1=7.8Hz  bin2=15.6Hz  ...  bin6=46.9Hz  bin7=54.7Hz  ...  bin15=117Hz
```

**特征 = 我们喂给 AI 的数字**。早期版本用"RMS + 全部 16 个频点" = 17 个特征。最终版本只用 5 个：RMS + bin1 + bin2 + bin6 + bin7。

---

## 第 3 章 神经网络是什么——用"加权评分"来理解

MLP（多层感知机）可以理解成一个**自动调好的加权评分系统**：

```
5 个特征 ──→ 16 个中间神经元 ──→ 8 个中间神经元 ──→ 3 个输出
(输入层)      (隐层1)             (隐层2)            (输出层)
```

- 每个箭头 = 一个**权重**（数字，可正可负）
- 每个神经元 = 把上游数字乘权重、加偏置、过一遍激活函数
- 输出层 3 个分数，最高分就是 AI 的答案（正常/松动/不平衡），softmax 把它变成概率（置信度）

**训练 = 自动调权重**。PC 上先给 AI 看几百条"特征+正确答案"的样本（监督学习），它自己把 259 个权重调到最佳——就像学生刷题调手感，刷完 388 道题（我们的样本数），考场上见新题也会做。

---

## 第 4 章 第一次尝试：17 特征模型——98.4% 的假繁荣

第一版模型：17 特征（RMS + 16 bin），结构 17→32→16→3，1155 个参数，5 折交叉验证 **98.4%**。

看起来完美，但它有一个致命盲区——**所有训练数据都是在 60% 电机占空比下采集的**。我们随后做了工业界最经典的检验：

**留一转速测试（Leave-one-speed-out）**：用 60/70/80/90/100% 五种转速中任意四种训练，用剩下一整种转速测试。结果：

| 模型 | 留一转速泛化准确率 |
|------|------------------|
| 17 特征 | **46.3%** |
| 20 特征 | 59.8% |

**46.3% ≈ 瞎猜水平（三分类瞎猜 33%）**。根因：**转速一变，频谱整体搬移**——60% 转速下 bin6=46.9Hz 恰好对准电机转动频率，70% 转速下转动频率挪到了 bin7，AI 在"旧地图"上认路，换了地图直接迷路。

**工程决策（重要！）**：工业设备通常工作在固定转速（风机、泵都是恒速运行）。与其硬扛多转速泛化，不如**锁定 60% 占空比作为演示工况**——这是产品需求决策，不是技术逃避。PCB 设计也按 60% 调校。

## 第 5 章 5 个鲁棒特征——为什么砍到 5 个

调试中发现第二个问题：**松动状态的频谱不稳定**——两颗螺丝全卸后频谱跳变严重，AI 学到的"松动指纹"不可靠。

解决方案：只保留 **物理意义最明确、最稳定**的 5 个特征：

| 特征 | 物理含义 | 为什么留它 |
|------|---------|-----------|
| RMS | 总振动能量 | 不平衡的剧烈振动一眼可见 |
| bin1 (7.8Hz) | 低频晃动 | 松动 = 低频晃动 |
| bin2 (15.6Hz) | 低频谐波 | 松动特征辅助 |
| bin6 (46.9Hz) | 转频附近 | 60% 转速的转动频率落在这 |
| bin7 (54.7Hz) | 转频谐波 | 不平衡的能量集中区 |

砍特征 = 砍掉噪声通道。**特征少、模型小、更不容易过拟合**——这是嵌入式 AI 的通用法则。

最终模型：**5→16→8→3，259 参数，5 折交叉验证 97.7% ± 2.5%，独立测试集 96.2%**。

混淆矩阵（独立测试集）：

```
             预测
实际      正常  松动  不平衡
正常       24     2      0
松动        1    24      0
不平衡      0     0     27
```

不平衡 27/27 全对——这是最重要的故障，漏报代价最高，全对。

## 第 6 章 5 折交叉验证是什么——模拟考制度

把 388 条样本平均分成 5 份：

```
轮1: [考] [练] [练] [练] [练]
轮2: [练] [考] [练] [练] [练]
...共5轮, 每份都当过考卷
```

- 每轮：4 份训练、1 份考试
- 5 个考试分数求平均 = **97.7% ± 2.5%**（±2.5% 说明模型稳定）
- 最后再用**完全没参与训练的独立测试集**考一次 = 96.2%

为什么要这么麻烦？防止"背答案"——如果只用一份数据既训练又考试，AI 可能死记硬背（过拟合），考场上原形毕露。交叉验证是 AI 界的模拟考制度，面试官认这个。

## 第 7 章 int8 量化——把 32 位体重压成 8 位

### 为什么需要量化

PC 训练的权重是 **float32**：每个数占 4 字节，还能带小数。单片机上 float32 又占 Flash 又慢。**int8** 每个数占 1 字节，整数运算在 Cortex-M4 上飞快。

### 对称量化原理（一句话版）

把 float32 的数**按同一把比例尺**压进 -128~127 的整数：

```
量化公式:  int8值 = round(float值 / scale)
反推公式:  float值 ≈ int8值 × scale

例子: 权重范围 -1.28 ~ 1.27, 取 scale=0.01
  float 0.5 → int8 50
  推理时: 50 × 0.01 = 0.5 ✓
```

每层一个 scale，存 6 个 scale 就够了。**scale 的选择原则**：让该层权重最大值刚好顶到 127，既不溢出也不浪费精度。

### 为什么零精度损失

在 PC 上把量化后的 int8 模型对全部测试数据跑了一遍：**float32 版 96.2%，int8 版 96.2%——0.00% 损失**。

原因：这个模型只有 259 个参数、2 个隐层，权重范围小，8 位精度完全装得下。**模型越小，量化越无损**——这是为什么我们要把 1155 参数砍到 259 的第二个理由。

### 量化收益

| 指标 | float32 | int8 | 收益 |
|------|---------|------|------|
| 权重占用 | 1036 字节 | 259 字节 | 省 75% Flash |
| 计算 | 浮点乘加（FPU） | 整数乘加（Cortex-M 单周期） | 更快 |

---

## 第 8 章 259 个参数怎么算出来的

结构 5→16→8→3，权重 + 偏置逐层相加：

```
第1层: 5×16 + 16 = 80 + 16 = 96     (每输入×每神经元一个权重, 每神经元一个偏置)
第2层: 16×8 + 8  = 128 + 8 = 136
第3层: 8×3 + 3   = 24 + 3  = 27
─────────────────────────────
总计: 96 + 136 + 27 = 259 个参数
```

对比第一版 17→32→16→3 = 17×32+32 + 32×16+16 + 16×3+3 = 576+528+51 = **1155 参数**。砍到 259 后：训练更稳（更不易过拟合）、Flash 占用更小、量化无损。**微型化的每一步都有明确理由。**

## 第 9 章 部署到 F407（全流程）

```
PC端 (Python, 你亲手跑过的脚本):
  collect_data.py   → 采集三工况数据 (Modbus 读 F407, 电机远程控制)
  train_simple.py   → 训练 5→16→8→3 MLP, 保存权重+归一化参数
  quantize_test.py  → int8 量化验证 (0.00% 损失)
  export_int8.py    → 自动生成 ai_model.h (int8 权重表 + 各层 scale + AI_MEAN/AI_STD)

F407端 (C代码):
  ai_classifier.c   → 读 ai_model.h, 整数运算推理, softmax 出置信度
  main.c            → 每 200ms: FFT → 归一化 → AI_Classify → 防抖(连续3帧) → 状态输出
```

归一化（AI_MEAN/AI_STD）：训练时把特征统一到"零均值、单位方差"，部署时用**同一套 mean/std** 做同样变换——训练和部署的数据预处理必须完全一致，这是部署 AI 的铁律。

实测：一次推理（259 参数 int8）在 168MHz F407 上 **<1ms**，200ms 任务周期里占比 <0.5%，实时性毫无压力。

## 第 10 章 这算不算边缘 AI（诚实版）

**算，理由**：
1. **全流程自研**：采集→特征工程→训练→交叉验证→量化→片上部署，没有跳步
2. **推理在设备端**：F407 上跑，不依赖云端，这就是"边缘"的定义
3. **有量化**：int8 部署是边缘 AI 的标志性技术
4. **有失败有决策**：多转速泛化失败→锁定工况，特征裁剪→鲁棒性，这是真实工程，不是玩具演示

**局限（面试被追问时的应对）**：
1. 模型是 MLP 而非 CNN/Transformer——但振动频谱分类用 MLP 足够，模型选择匹配问题复杂度
2. 没用 Cube.AI/TFLM 工具链，手写推理代码——**反过来是加分项**：你懂量化和推理的内部原理，工具链只是加速器
3. 三分类、388 样本——样本量确实小，但工业故障数据本来就稀缺，交叉验证保证了结论的可信度

**面试定位话术**："这是一个完整的微型边缘 AI 工程——从特征工程到 int8 量化部署，模型只有 259 个参数、1KB Flash 占用，96.2% 准确率，而且我是从'为什么 17 特征失败、为什么砍到 5 个'一步步推演出来的，不是抄教程。"
