## 二、PCB 硬件与面包板的差异（固件必须知道的）

| # | 差异 | 影响 |
|---|------|------|
| 1 | **LSE 32.768kHz 外部晶振新增**（PC14/PC15） | 🔴 CubeMX 必须改 RCC LSE=Crystal，否则晶振白焊、RTC 仍跑 LSI |
| 2 | **PB0 改为蜂鸣器**（原 ESP8266 EN，已废弃） | 需新增蜂鸣器驱动代码 |
| 3 | **PA0 黄灯、PA1 红灯新增** | 需新增 LED 控制代码（绿灯 PC0 已是心跳灯，无需改） |
| 4 | **MPU6050 已从 PCB 移除** | 代码里 MPU6050_ReadAccel 读取但值未用，可删 |
| 5 | RS485 芯片 = MAX13487E（5V 供电，HT7150 单独供 5V） | 逻辑电平已验证兼容（PB11/PD8 均 FT 脚） |
| 6 | MAX13487E 无 DE 脚：Pin2=RE、Pin3=SHDN，短接后 10kΩ 上拉到 5V = AutoDirection 自动收发 | 默认 0Ω 不焊，无需代码控制方向 |
| 7 | 0Ω(DNP) 接 PC8 = 备份：焊上后 PC8 拉低 = 关断 485 芯片（软件复位用） | 不是方向控制！ |
| 8 | PC6/PC7 各 10kΩ 下拉（复位期防电机误动） | 代码无需改，Motor_Init 已有 |
| 9 | ESP32 模组 = ESP32-S3-WROOM-1（邮票孔，USB 原生烧录口） | ESP32 固件按 S3 配置（GPIO16=RX2、GPIO17=TX2） |
| 10 | USART3 115200（面包板最终配置） | modbus_slave.c:128 的 LOG 还写着"9600 8N1"，是旧日志没改 |
| 11 | 电机物理开关 SW3（12V 到 TB6612 VM 之间） | 演示时手动控制电机通断电 |

## 三、软件待办清单（按优先级）

### 🔴 P0：CubeMX 改 LSE（必做，不改 PCB 白焊）
1. 打开 Vibration_F407.ioc → System Core → RCC → LSE 选 **Crystal/Ceramic Resonator**
2. Clock Configuration 里 RTC 时钟源选 LSE
3. Generate Code **前先备份 main.c 全文**
4. Generate 后逐项检查（历史踩坑）：
   - MX_IWDG_Init() 位置（必须挪到 osKernelStart() 前，否则看门狗提前启动复位循环）
   - USART3 波特率是否被改回 9600（必须 115200）
   - FreeRTOS 任务函数体是否被清空（USER CODE 标记断裂，历史坑14）
   - HAL 时基 TIM6、中断优先级

### 🟡 P1：新增 PCB 输出驱动（蜂鸣器 + 黄灯 + 红灯）
初始化（main.c USER CODE BEGIN 2）：
```c
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_0 | GPIO_PIN_1, GPIO_PIN_SET); // 黄/红灭（低电平亮）
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_0, GPIO_PIN_RESET);             // 蜂鸣器不响
```
阈值逻辑骨架（sensorTask 每轮采样后，阈值待 AI 训练后替换）：
```c
if (fft_result.rms > 2.0f) {          // 故障：红亮+蜂鸣
    PA1=0; PA0=1; PB0=1;
} else if (fft_result.rms > 0.5f) {   // 预警：黄亮
    PA0=0; PA1=1; PB0=0;
} else {                              // 正常：全灭，绿灯心跳
    PA0=1; PA1=1; PB0=0;
}
```

### 🟡 P2：RS485 方向备份（仅当 AutoDirection 丢包才做）
- 现状：modbus_slave.c 发送用寄存器直写，未调用方向切换
- 若 115200 下丢包：焊上 0Ω，代码在 Modbus_Poll 发送前 `RS485_SetTx()`、`while(TC)` 后 `RS485_SetRx()`（函数已存在于 modbus_slave.c:102-110，只是没被调用）
- 注意：MAX13487E 拉低 RE/SHDN = 关断芯片，不是方向控制；备份用途是"软件复位 485"

### 🟢 P3：代码清理（不强制）
| 项 | 操作 |
|----|------|
| 删除 MPU6050 | mpu6050.c/h + main.c include + sensorTask 里的 ReadAccel 调用 + ax/ay/az 变量 |
| 删除 ESP8266 | esp8266.c/h + main.c include |
| I2C1 互斥锁 | 可选删（I2C1 上只剩 OLED 一个设备） |
| Modbus 日志 | modbus_slave.c:128 的 "9600 8N1" 改为 "115200 8N1" |

### 引脚分配锁定表（PCB 已按此设计，不可改）
- USART1: PA9(TX)/PA10(RX) → ESP32
- USART2: PA2/PA3 → 调试
- USART3: PD8(TX)/PB11(RX) → MAX13487E
- PC8: RS485_DE（0Ω 备份）
- I2C1: PB6/PB7 → OLED
- SPI1: PA5/PA6/PA7 + PA4(CS) → ADXL345
- SPI2: PB10(SCK)/PC2(MISO)/PC3(MOSI) + PB12(CS) → W25Q64 ⚠️ 非标引脚
- TIM3_CH4: PB1 → 电机 PWM 1kHz
- PC6/PC7: 电机 AIN1/AIN2；PB2: STBY+BOOT1
- PB5: DS18B20
- PC0: 绿 LED；PA0: 黄；PA1: 红；PB0: 蜂鸣器

## 六、教学方式铁律（新对话必须遵守）

1. 每一步列完整操作细节（点哪个菜单、选什么、填什么值）
2. 代码写在哪、USER CODE BEGIN/END 哪个块之间要讲清楚
3. 出错了先要现象描述 → 分析根因 → 给修复步骤，不让用户自己猜
4. CubeMX Generate Code 必毁三样：IWDG 位置、波特率、USER CODE 块——每次生成后检查
5. 用户指出错误时，承认并立即修正，不狡辩
6. 一切以跑通版本为准，不确定的先问再动
